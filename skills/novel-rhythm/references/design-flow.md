# 辅助开发流（提问式共创）脚本

> 本文件是 SKILL.md 第二节的详细脚本：**模型接着 agent，向作者提问，把作者内心想写的小说"问"出来。**
> 使用节奏：第一次打开插件 = 看样板（`../tools/rhythm-viewer.html` 内置 20 章示范）；之后 = 本文件：进入开发流。
> 进入开发流后再加载本文件；先读"总则"，再按作者选的路径读对应脚本。

---

## 一、总则（四句话）

1. **提问纪律**：一次最多问 1~2 个问题，等作者回答再继续；每题自带"我的建议/默认值"（2~3 个具体选项），作者可以只回"听你的"。
2. **挖内心，不挖流程**：问的是"您想看到什么 / 爽在哪 / 意难平什么 / 想避开什么"，不是问卷表。
3. **边问边记**：随手维护"设计底稿"（格式见第五节），每 2~3 轮向作者复述一次，确认没记偏。
4. **命名约定**：结构层一律用功能位 + 描述性称谓；作者自己的命名随行括注（如"女主1（作者命名：XX）"），二者不混用。

---

## 二、入口问路（开场模板话术）

只说这两句，给作者二选一，不要展开成问卷：

> 两种起步方式，您挑一个顺手的：
> **A.【先定节奏曲线】** 您给我一个想法，哪怕一句话——我把它"拉伸"成一整本书的节奏曲线（哪里扬、哪里落、哪里爆发），然后再逐章细化。
> **B.【先落地章节】** 您先说说最想写的那个场景/桥段——我按章内节拍，陪您一拍一拍排出来，排着排着整条曲线自己会长出来。
> （说"都行"也可以，我按 A 开场。）

作者答完再进入对应脚本。**不要**在问路的同时追问题材、主角、设定——路径没定，问了也白问。

---

## 三、路径 A 脚本：先定节奏曲线

### A1 · 收种子

要**一个想法**即可：一个场景、一个设定、一个画面、一种情绪都行。

作者说"没有想法"时，用内心三问引导（一次问一条，别连发）：

- "最近哪种故事让您上头？您想让读者读到您这本书时，最强烈的感受是什么？"
- "有没有什么'意难平'——别的书没写爽的点，您想自己写一遍？"
- "有没有明确不想写的（桥段/节奏/类型雷区）？"

### A2 · 拉伸四问（种子的第一轮拉伸）

按此顺序问，每问给默认值：

1. **题材与舞台**："故事发生在什么样的地方？封闭式集体环境（学院/宗门/基地/公署这类，规则严、出不去），还是开放世界走江湖？"→ 决定【主舞台】功能位的具象。
2. **主角处境**："主角开局是被架在火上（最公开、不能逃、随时暴露），还是隐在暗处（低调攒资源、闷声干大事）？"→ 决定第一浪的压迫强度。
3. **核心矛盾**："主角身上背着一个必须对抗的负担（倒计时/契约/诅咒），还是一个必须隐藏的身份？"→ 决定暗线形态。
4. **情绪波形**："您希望读者的体验是：一路爽 / 先憋后爽 / 甜虐交替？"→ 决定张力密度策略（爽向=高位密集；憋向=前段压低后段爆发）。

顺带完成一问：**篇幅目标**（预计多少章/多少卷）→ 决定浪的数量。

### A3 · 节奏化拉伸算法（把一句话拉成整本书骨架）

按五步走，产出可直接播报给作者：

1. **找核心循环**——判定问法："这个想法里，主角每次做完哪个动作，会获得什么、付出什么、又冒出什么新问题？"
   - 答得上来 = 可重复单元成立（做 X → 得 Y → 付代价 Z → 回到 X 但更高一层），长篇立得住；
   - 答不上来，先陪作者把想法"循环化"，再往下走。
2. **定三段浪**：危机浪（立压迫与核心矛盾）→ 铺设段（交付体系/伙伴/目标）→ 获取浪（主动出击、爽点、主题升华）。按篇幅伸缩：短篇压成两浪，长篇加段。
3. **铺张力曲线**：套 M 型双浪骨架（高点开局→设定→喜剧回落→真惊吓→落地→低位铺设→转折→爽点→高潮→收获→喘息→蓄力→循环钩），按 A2 的情绪波形调密度。
4. **造曲折**（见 A4）。
5. **落章节节点**：逐章选模板（T1~T13 或变体）+ 一句话功能 + 尾钩类型（三选一轮换）。

### A4 · 造曲折：三件套（把平铺的想法压出起伏）

| 曲折件 | 做法 | 撒点节奏 |
|---|---|---|
| 踩坑拍 | 预期落空：主角按计划走，结果被打断/被误解/被截胡 | 每浪 1~2 次 |
| 代价拍 | 收获伴随代价：力量/道具到手，同时付出不可逆的代价 | 每次大收获同章 |
| 转向拍 | 目标升级或新威胁：旧目标解决，更大的问题浮出 | 浪尾/阶段终点 |

撒完对照规则自检：喘息章紧邻高潮后、爽点间隔 3~5 章、强钩只放浪首浪尾、每约 5 章一拍真惊悚。

### A5 · 拧曲线（交给作者调整）

给作者看两样东西：**ASCII 曲线** + **章节节点表**，然后只问三句：

- "哪一段您觉得太慢？"
- "哪一段太急（还没看够就过去了）？"
- "哪里不够爽 / 哪里太满，需要留白？"

按回答调整 1~2 轮；推荐顺手生成 `rhythm-data.json` 让作者打开查看器边看边拧。

### A6 · 章节内部设计（曲线定了以后）

对作者点名的章（或从第 1 章起逐章），按五拍骨架**逐拍问**，每拍给模板候选建议：

| 拍 | 问法 | 基于模板的候选示例（T11 时） |
|---|---|---|
| 衔接拍 | "这章开场第一个画面是什么？从哪里接上一章？" | 接上章尾钩的余波 / 换场景直入 |
| 新要素拍 | "这章只上一个新东西——新人、新规则、新道具还是新情报？" | 势利商人登场（新角色） |
| 主事件拍 | "这一章的'看家戏'是哪一场？读者合上这章会记住什么？" | 懂行压价 / 平静全款 / 商人震惊 |
| 回落拍 | "事情办完的余波：谁来收尾？代价是什么？紧张还是喜剧？" | 插叙积累史（努力前置） |
| 尾钩拍 | "最后停在什么'没完成'上？数值变动 / 谶语 / 待验证，三选一。" | 回据点研读手册，用法成谜 |

整章问完，给"章内趋势"预览（如 `3 → 4 → 5 → 3 → 3`），并对照"章内曲线四型"检查形状。

## 四、路径 B 脚本：先落地章节

### B1 · 收场景

要"您现在最想写的那个画面/桥段"（一段戏即可，不需要完整）。

### B2 · 模板匹配（把场景放进节奏里）

把场景与 13 模板做匹配，给作者 2~3 个最接近的候选让他选，例如：

> 您这个"主角被轻视后掏钱结账"的场景，我匹配到三个位置：
> ① T11 憋屈→打脸（先被压、再翻身，最像）；
> ② T12 制作流高潮（如果是"亲手造出关键物"的场面更贴）；
> ③ T3 流水线登场（如果重点是引出新角色）。
> 您觉得哪个更像？这决定它的张力档和前后怎么接。

选定后确定：章型 + 张力档 + 在曲线上的大致位置。

### B3 · 逐拍排（五拍问法同 A6）

一拍一问，模型先给建议、作者做选择或改；整章排完给"章内趋势"预览。

### B4 · 曲线自生长（一对一地问下去）

每章收尾只问一句：

> "下一章想先**加压**（新威胁/新冲突），还是先**放松**（日常/糖/喘息）？"

按回答生成下一章的章型与张力。三条伴随规则：

1. **每 3~4 章一次曲线盘点**：把已排的章串成 ASCII 曲线，检查喘息位置 / 爽点间隔 / 尾钩轮换 / 是否缺一拍真惊吓，向作者播报。
2. **排到第 5~8 章，必须补问全书终点**："这本书最终要解决的是什么？主角最后会变成什么样？"——B 路径容易缺长线，此时补一份**轻量全书骨架**（只定浪与暗线，不定逐章）。
3. 节奏掉到低位太久（连续 3 章张力 ≤2）主动提醒："要不要安排一次加压 / 一个爽点？"

### B5 · 收敛

排满目标章数（或作者喊停）后，收敛为粗纲（见第六节）。

---

## 五、中间产物：设计底稿（边问边记）

```md
# 设计底稿
## 0. 一句话想法
## 1. 题材与舞台（功能位 + 作者命名）
## 2. 主角（处境 / 核心矛盾 / 作者命名）
## 3. 想要的情绪波形（作者原话 → 曲线策略）
## 4. 篇幅目标（章数 / 分段）
## 5. 核心循环（做 X → 得 Y → 付代价 Z）
## 6. 作者命名表（角色 / 场所 / 体系 / 道具 → 功能位映射）
## 7. 访谈关键问答（带轮次）
```

每 2~3 轮复述给作者确认；**若作者确认要落盘，另存为 `设计底稿.md`**（不落盘则留在对话里）。

---

## 六、收敛产物：粗纲（两条路径统一）

用 `../templates/rough-outline.md` 模板输出三件套：

1. **分段与曲线**：分段表 + ASCII 曲线；
2. **章节粗纲**：每章一行块——标题 / 模板 / 张力 / 一句话功能 / 尾钩 / 拍点链 / 章内趋势；
3. **可视化数据**：`rhythm-data.json`（格式见 `outline-schema.md`）→ 作者进查看器拧曲线。

粗纲成型前先过一遍铁律自检（一新增 / 尾钩 / 上锁 / 前置）。

---

## 七、交接：粗纲之后，作者二选一

> "粗纲到这儿就成型了。接下来您可以：① **自己接着写**——我给您一份写作交接包；② **让我继续设计**——选几章细化下去。"

**① 写作交接包**（给作者自写用）——每章一张写作提示卡：

```md
### 第 N 章 写作提示卡
- 模板 / 张力 / 章内趋势：
- 拍点链（逐拍要点）：
- 本章唯一新增：
- 尾钩（类型 + 内容）：
- 承接：上一章留下的钩子怎么接：
- 提醒：若给爽 → 限制拍怎么写；若给爽 → 回溯拍放哪
```

**② AI 继续细化**（受约束的续设计）：
- 范围：作者选的章（或下一批章节）；
- 动作：把拍点链落到**逐场景细纲**——每场景一行（场所 / 在场角色 / 发生什么 / 结束时状态与钩子）；
- 约束：不得偏离已定章内趋势与铁律；新增设定先向作者确认；改节奏先问作者。

## 八、常见回复的处理

| 作者的回复 | 处理 |
|---|---|
| "随便 / 都行 / 听你的" | 用默认值并**说明理由**，继续推进（不空转、不反复问） |
| "不知道写什么" | 回到内心三问（上头什么 / 想给读者什么感受 / 想避开什么） |
| 一次性倒出大量设定 | 先归类到功能位，挑"最影响节奏的一条"先落曲线，其余记入设计底稿 |
| "别问了，直接给我粗纲" | 走**快速模式**：用默认骨架 + 三问确认（题材 / 主角处境 / 情绪波形），产出"待校准粗纲"，并在开头标注哪些是默认值 |
| 想让插件评价题材好坏 | 不做价值评判；只做**节奏诊断**（引用规则说话："这里喘息章离高潮太远"） |

## 九、拉伸样例（对着讲）

把"一句话种子"拉成整本书的完整样例 = `../examples/demo-outline.md`（20 章：分段 → 曲线 → 节点 → 章内节拍）。
向作者解释拉伸结果时，可直接指着这份样例说："您的书会是这个形状，只是内容全换成您的。"
