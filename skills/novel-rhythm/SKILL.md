# 节奏工坊 · 网文章节节奏系统

> 把一部连载长篇的节奏拆成三层来做：**先定全书节奏（章节节点 + 可视化曲线）→ 每个节点内用章节模板规范章内节拍 → 章内节拍同样有曲线可查**。
> **两种打开方式**：第一次 = 看样板（打开查看器看 20 章示范）；之后 = 辅助设计（按第二节"开发流"，向作者提问，共创新书粗纲）。
> 本文档内所有人名、场所、体系、道具、事件均已通用化为【功能位】与描述性称谓，不含任何原作专名；生成内容时同样必须遵守第七节的"通用化写作规则"。

---

## 何时调用

- **设计新书（提问式开发流）**：作者说"我想写一本……""帮我设计""不知道从哪开始"→ 走第二节
- **看样板**：作者想看效果、想了解这套方法 → 引导打开查看器（内置 20 章示范），看完主动问一句"要不要开始设计您自己的书？"
- **看写作实况**：章节写完后想把正文直接可视化、或核对粗纲兑现度 → 走第五节"方式二"（写作实况曲线查看器）
- **直接性任务**（跳过访谈直说需求）：排全书节奏 / 写某章的章纲 / 审已有章纲的节奏 / 出可视化 → 直接走第三~五节

---

## 一、三层体系总览

| 层级 | 回答的问题 | 产物 | 可视化 |
|---|---|---|---|
| 全书层 | 一串章怎么呼吸？ | 分段（浪）+章节节点表（模板/张力/类型/功能/尾钩） | 全书张力曲线 + 章节节点（查看器主视图） |
| 章节层 | 这一类章该长什么形状？ | 从 13 种章节模板选定拍点链 | 节点标记（类型符号） |
| 节拍层 | 这一章内部一拍一拍怎么走？ | 章内拍点链 + 每拍张力值 | 章内节拍曲线（点节点下钻） |

张力标尺（全系统统一）：**1=舒缓/情感，2=日常，3=小起伏，4=高潮/爽点，5=强钩子**。

五拍骨架（每章公共结构，各拍配重随模板调整）：

```
衔接拍（承接上章钩子/场景入场）
  → 新要素进场拍（新角色/新系统/新道具/新信息，一章只上一个新的）
  → 主事件拍（本章存在的理由：一次冲突/一次展示/一次研究/一次获取）
  → 回落拍（结果落地、数值盘点或喜剧收尾）
  → 尾钩拍（章末悬念：数值变动 / 谶语悬念 / 结果待验证，三选一轮换）
```

## 二、开发流：辅助作者设计（提问式共创）

> 模型接着 agent，**向作者提问**，把作者内心想写的小说"问"出来。本节只保留协议骨架；详细提问脚本与话术模板见 [references/design-flow.md](references/design-flow.md)，进入开发流后加载。

### 2.1 入口问路（先问清走哪条路，不要先问设定）

开场给作者二选一：

> **A.【先定节奏曲线】** 给我一个想法（一句话也行），我把它"拉伸"成一整本书的节奏曲线，然后再逐章细化。
> **B.【先落地章节】** 您先说说最想写的那个场景/桥段，我按章内节拍陪您一拍一拍排，串起来曲线自己会长出来。

### 2.2 提问纪律（全程硬约束）

1. 一次最多问 1~2 个问题，等回答再继续；禁止一次性抛问题清单。
2. 每题自带"我的建议/默认值"（2~3 个具体选项）；作者可以只回"听你的"。
3. 问的是作者的**内心**：想看到什么、爽在哪、意难平什么、想避开什么——不是流程表单。
4. 边问边记"设计底稿"（格式见 design-flow.md 第五节），每 2~3 轮复述确认。
5. 命名：结构层用功能位 + 描述性称谓；作者自己的命名随行括注（如"女主1（作者命名：XX）"）。

### 2.3 路径 A：先定节奏曲线（想法 → 拉伸曲折 → 章节内部设计）

1. **收种子**：要一个想法（场景/设定/画面/情绪皆可）；没有就用"内心三问"引导。
2. **节奏化拉伸**：找核心循环（做 X → 得 Y → 付代价 Z）→ 定三段浪 → 套 M 型双浪铺张力 → 造曲折（**三件套**：踩坑拍 / 代价拍 / 转向拍）→ 落章节节点（模板 + 一句话功能 + 尾钩）。
3. **拧曲线**：出示 ASCII 曲线 + 节点表，只问三句（哪段太慢/太急/不够爽），调 1~2 轮；推荐生成 `rhythm-data.json` 进查看器拧。
4. **章节内部设计**：对作者点名的章（或从第 1 章起），按五拍骨架**逐拍问**，每拍给模板候选建议，产出章内拍点链与章内趋势。
5. 收敛为粗纲（见 2.5）。

### 2.4 路径 B：先落地章节（场景 → 逐拍排 → 曲线自生长）

1. **收场景**：要"最想写的那个画面/桥段"。
2. **模板匹配**：给 2~3 个最接近的模板候选让作者选，定章型与张力档。
3. **逐拍排**：按五拍骨架一拍一问（问法同 2.3 第 4 步）。
4. **曲线自生长**：每章收尾问"下一章加压还是放松？"→ 生成下一章章型与张力；每 3~4 章做曲线盘点（喘息/爽点间隔/钩子轮换/真惊吓）；排到第 5~8 章必须补问全书终点，补一份轻量全书骨架（只定浪与暗线）。
5. 收敛为粗纲（见 2.5）。

### 2.5 收敛：粗纲（两条路径统一产物）

- 用 [templates/rough-outline.md](templates/rough-outline.md) 输出：① 分段与 ASCII 曲线；② 章节粗纲（标题/模板/张力/一句话功能/尾钩/拍点链/章内趋势）；③ `rhythm-data.json` 供查看器拧曲线。
- 成型前过一遍第六节铁律自检。
- 成型后**交接给作者二选一**：
  - ① **作者自己写**：给"写作交接包"（每章写作提示卡：拍点链 + 尾钩 + 钩子承接 + 爽点/限制/前置提醒）；
  - ② **AI 继续设计**：挑章细化成逐场景细纲，受已定章内趋势与铁律约束；新增设定先确认、改节奏先问作者。

## 三、工作流 A：全书节奏规划（先定完整节奏）

**第 1 步 · 定浪分组**
把全书切段（每段 = 一浪/一个区间/一组事件），每浪起点放一个 **T10 转折宣言章**，浪尾接 **T5 收束** 或 **T9 喘息**。20 章样板的三段结构（可直接借用）：

```
危机浪（1~5）→ 体系铺设段（6~12）→ 获取实验浪（13~20）
```

**第 2 步 · 排章节节点**（每章定六个字段）

| 字段 | 说明 | 示例 |
|---|---|---|
| 章号 | 顺序位 | 15 |
| 节点标题 | 该章一句话名字 | 财力打脸 |
| 模板 | 13 模板之一或变体 | T11 |
| 张力 | 1~5，对照曲线排 | 4 |
| 类型 | 钩子章/设定章/登场章/机制章/信息章/伏笔章/转折章/铺垫章/爽点章/高潮章/收获章/喘息章/铺设章/蓄力章 | 爽点章 |
| 一句话功能 | 本章存在的理由 | 购得核心道具+财力打脸 |
| 尾钩 | 三选一，轮换不重样 | 操作悬念（实际怎么用） |

**第 3 步 · 曲线自检**（逐条过，任何一条不过就调整节点）

- 喘息章（张力 1）紧邻高潮/小高潮之后的下一章，无强钩
- 爽点每 3~5 章一个，类型轮换：过关 → 碾压 → 打脸 → 认可
- 强钩章（张力 4~5 的钩子章）只放浪首/浪尾，中段章用轻钩维持连载动力
- 每约 5 章安排一拍真惊悚（T5 类），防止基调一路喜剧化
- 关键角色每 1~2 章引入一名，全部"场合顺带"登场，禁止专程开章介绍
- 主视角连续 3~4 章后插一章视角切换/群像喘息（T9）
- 尾钩三选一（数值变动/谶语悬念/结果待验证）轮换使用

**第 4 步 · 生成可视化数据**（可选但推荐）
按 `references/outline-schema.md` 的格式写出 `rhythm-data.json`，即可用查看器出全书曲线（见第五节）。

## 四、工作流 B：章内节拍设计（规范章内节拍）

**第 1 步 · 按节点模板取拍点链**
查 `references/chapter-templates.md`（13 模板全量：拍点链 / 每拍作用 / 章末钩 / 通用槽位 / 复用要点）。逐章示范可查 `references/beat-chains.md`。

**第 2 步 · 用五拍骨架校准**
模板拍点链填入五拍骨架：衔接 → 新要素 → 主事件 → 回落 → 尾钩。拍数可 4~6，但五类功能位不得缺失。

**第 3 步 · 逐拍赋张力，得到章内曲线**
每拍标一个张力值（1~5），对照"章内曲线四型"检查形状：

| 章内曲线型 | 适用章 | 形状 |
|---|---|---|
| 单峰型 | 爽点章、高潮章 | 2 起 → 爬升 → 4~5 峰（主事件）→ 回落 → 尾钩 3~4 |
| 高位贯穿型 | 钩子章、转折章 | 3~4 起 → 持续高位 → 尾钩拍到 4~5 |
| 双峰型 | 信息章、机制章 | 2~3 → 小峰 4 → 回落 → 再升 4 → 尾钩 |
| 低谷平缓型 | 喘息章 | 1~2 贯穿全章 → 尾钩轻抬到 2~3 |

硬性要求：**章内最高点必须落在主事件拍上；尾钩拍必须停在"未完成态"**（问题抛出、本章不回答）。

**第 4 步 · 章内自检**
见第六节"每章及格线"。产出物是一张"单章节拍卡"（模板见 `templates/chapter-beat-card.md`）：拍名 / 节拍张力 / 内容 / 节奏功能。

## 五、工作流 C：可视化

**方式一：规划曲线查看器（排章阶段用）**

1. 按 `references/outline-schema.md` 写数据文件 `rhythm-data.json`（纯 JSON）
2. 双击打开 `tools/rhythm-viewer.html`（单文件、离线可用）
3. 用"导入"载入数据：拖拽文件 / 选择文件 / 粘贴 JSON 均可
4. 主视图 = 全书张力曲线 + 章节节点；**点击任意章节节点**下钻查看该章的模板、尾钩与章内节拍曲线
5. 可用"导出 SVG"保存当前全书曲线图片

内置 20 章样板数据在 `tools/demo-rhythm-data.js`，打开查看器即可看到（不用导入）。

**方式二：写作实况曲线查看器（写完章节后直接看）**

适用：已写出若干章正文，想看"实际写出来的节奏"是否兑现了粗纲——先看多章节实况，再按需下钻章内曲线。

1. 双击打开 `tools/written-rhythm-viewer.html`（单文件、离线）
2. 把章节文件（`.md` / `.txt`）或整个文件夹**拖进页面**（也可"选择章节文件 / 选择文件夹 / 粘贴文本"；多章粘贴用一行 `===` 分隔）
3. 自动按"第 N 章"排序 → 主视图 = **多章节实况曲线**；点任意章节节点 → 章内曲线（右上角「章内曲线」开关，此为可选层，关闭后只看章节级）
4. 数据来源两级，**标注优先、估算兜底**：
   - **标注**：章节文件开头写一行节奏标注 → 张力/类型/模板/节拍直接读取（格式见 `references/outline-schema.md` 第五节）
   - **估算**：未标注的章由"字数 · 对话占比 · 动作情绪词密度"推得，界面明确标"估算"，仅供趋势参考
5. **对比粗纲（可选）**：点「对比粗纲」导入 `rhythm-data.json` → 计划曲线以虚线叠加、章内节拍与实况同屏对照（兑现度检查）
6. 页面内「载入演示」含 5 章虚构片段（标注与估算两种都已展示）；可"导出 SVG"

写作流程建议：让 AI 每写完一章，顺手在章节文件开头补一行标注（已有存稿也可让 AI 逐章回补），实况曲线就会越来越准。

**方式三：对话内 ASCII 曲线（快速汇报）**

```
章节:  1  2  3  4  5  6  7  8
张力:  5  4  2  2  3  2  2  2
      ★钩 ★设 ▼喜 ▼喜 ▲惊 ▼机 ▼设 ▼设
```

渲染规范：数字行按列对齐；标记行 = 节点标记符 + 类型单字。
节点标记符：`★`=峰值章（张力≥4），`▲`=高位章（张力3），`▼`=低位章（张力≤2）；数据里手工指定的 `dir` 字段优先。
类型单字：钩/设/喜/机/息/伏/转/铺/爽/收/蓄/惊（登场章用"喜"，落地章用"惊"）。

## 六、每章及格线（一章铁律）

1. **一章一新增**：每章只引入一个新角色/新系统/新道具/新信息，其余拍点全部用来消化它。
2. **尾钩必留**：最后一段停在未完成态；尾钩三选一轮换，不重样。
3. **爽后上锁**：给力量/道具的章，同章必须附使用限制，防金手指万能化。
4. **努力前置**：给爽点的章配一个回溯拍（插叙积累/凭旧表现换资源），禁止凭空爽。
5. **元规则**：以上缺一即拆章或并章。

## 七、通用化写作规则（硬约束）

生成任何内容（节点表、拍点链、数据文件、文档）时：

1. **零专名**：本插件的知识库、模板、示范内容一律不出现书名、作者名、角色本名、金手指原名、组织名、地名、事件专名。
2. **人物 = 功能位代号 + 描述性称谓**：主角 / 女主1~4 / 角色A~H；称谓一律用描述式，如"高贵的女人""出身低微的孤女""才智出众的女人""成熟年上的管理者""命运之子""势利的商人""授课的长者""和蔼的长者""高阶强者"。
3. **身份不写头衔**：凡设定专属爵位/职衔（大小姐、圣女、长老、首席之类）→ 转译为描述性称谓（见 `references/universal-slots.md` 的转换示例表）。
4. **场所/体系/道具/事件先落功能位**（主舞台、反向数值系统、自制道具体系、限时交易场、长线赛事、秘藏文献区……），再按新书世界观具象化命名；具象化只改名词层，不许改节奏功能层（拍点链、张力、尾钩类型保持不变）。
5. **为作者设计新书时的命名分栏**：结构层（节奏表/模板/拍点链）始终用功能位与描述性称谓；作者自己的命名随行括注（"女主1（作者命名：XX）"）——保证"换名不换骨"，节奏结构不依赖任何具体专名。
6. **判定标准**：把生成物给不了解原作的人看，对方应能直接套用到任何题材的书上。
